# Labs 031-040 — Remote Git

## Lab 031 — Add a remote
**Objective:** Connect local Git to GitHub. **Commands:** `git remote add origin <repo-url>`; `git remote -v`. **Expected:** origin is listed. **Task:** Explain fetch vs push URLs. **Challenge:** Rename origin. **Solution:** `git remote rename origin upstream`. **Interview:** What is a remote?

## Lab 032 — Push a branch
**Objective:** Publish a local branch. **Commands:** `git push -u origin feature/name`. **Expected:** Remote branch exists and upstream is configured. **Task:** Run `git branch -vv`. **Challenge:** Push another branch without -u. **Solution:** First push establishes tracking. **Interview:** What does `-u` configure?

## Lab 033 — Clone a repository
**Objective:** Create a working copy. **Commands:** `git clone <repo-url>`; `cd repo`; `git remote -v`. **Expected:** Repository and origin exist. **Task:** Inspect branches. **Challenge:** Clone into a custom directory. **Solution:** `git clone <url> <directory>`. **Interview:** What does clone download?

## Lab 034 — Fetch without merging
**Objective:** Update remote-tracking refs safely. **Commands:** `git fetch origin`; `git log origin/main --oneline`. **Expected:** Remote-tracking data updates without changing your branch. **Task:** Compare local main and origin/main. **Challenge:** Fetch all remotes. **Solution:** `git fetch --all`. **Interview:** What does fetch not do?

## Lab 035 — Pull with explicit strategy
**Objective:** Understand pull composition. **Commands:** `git pull --ff-only`; alternatively `git pull --rebase`. **Expected:** Local branch incorporates remote work according to chosen strategy. **Task:** Explain fetch+merge/rebase. **Challenge:** Configure a preferred pull behavior. **Solution:** Use `git config --global pull.rebase true` or an explicit command. **Interview:** Why can pull create conflicts?

## Lab 036 — Track a remote branch
**Objective:** Configure branch tracking. **Commands:** `git switch -c feature --track origin/feature`. **Expected:** Local feature tracks remote feature. **Task:** Inspect `git branch -vv`. **Challenge:** Set upstream later with `git branch -u origin/feature`. **Solution:** Use `--track` or `-u`. **Interview:** What is an upstream branch?

## Lab 037 — Delete a remote branch
**Objective:** Remove obsolete remote work. **Commands:** `git push origin --delete feature`. **Expected:** Remote branch is deleted. **Task:** Prune local remote-tracking refs with `git fetch --prune`. **Challenge:** Explain local branch deletion vs remote deletion. **Solution:** They are separate refs. **Interview:** What does --prune do?

## Lab 038 — Inspect remote state
**Objective:** Diagnose synchronization. **Commands:** `git remote show origin`; `git branch -r`; `git status -sb`. **Expected:** Tracking and divergence details appear. **Task:** Identify ahead/behind state. **Challenge:** Find stale branches. **Solution:** Fetch and prune. **Interview:** What does ahead/behind mean?

## Lab 039 — Handle non-fast-forward push
**Objective:** Recover from rejected push. **Scenario:** Remote contains commits you lack. **Commands:** `git fetch origin`; inspect; integrate with merge or rebase; push. **Expected:** Push succeeds without overwriting unrelated work. **Task:** Draw the history before/after. **Challenge:** Explain why force push is not the first choice. **Solution:** Synchronize first. **Interview:** What causes non-fast-forward rejection?

## Lab 040 — Practice safe force push
**Objective:** Understand rewritten branch publication. **Commands:** After a deliberate local rebase on a private branch, use `git push --force-with-lease`. **Expected:** Remote accepts the rewritten history if it still matches your expectation. **Task:** Compare with `--force`. **Challenge:** Explain when force pushing a shared branch is dangerous. **Solution:** Prefer `--force-with-lease` and private branches. **Interview:** Why is force-with-lease safer?

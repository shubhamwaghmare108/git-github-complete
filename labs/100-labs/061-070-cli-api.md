# Labs 061-070 — GitHub CLI and API

## Lab 061 — Verify GitHub CLI
**Objective:** Confirm `gh` authentication. **Commands:** `gh --version`; `gh auth status`. **Expected:** CLI version and authentication state appear. **Task:** Explain what account is active. **Challenge:** Re-authenticate. **Solution:** Use `gh auth login`. **Interview:** Why use CLI automation?

## Lab 062 — Clone with GitHub CLI
**Objective:** Clone a repository using `gh`. **Commands:** `gh repo clone OWNER/REPO`. **Expected:** Local working copy appears. **Task:** Inspect its remote. **Challenge:** Clone into a named directory. **Solution:** Pass the destination directory. **Interview:** How does gh complement Git?

## Lab 063 — View a repository
**Objective:** Query repository metadata. **Commands:** `gh repo view OWNER/REPO`; `gh repo view OWNER/REPO --web`. **Expected:** Repository information and browser view are available. **Task:** Identify default branch. **Challenge:** Script selected fields with JSON output. **Solution:** Use structured output options. **Interview:** Why is structured output useful?

## Lab 064 — Create an issue from CLI
**Objective:** Automate issue creation. **Commands:** `gh issue create --title "..." --body "..."`. **Expected:** Issue URL is returned. **Task:** Add labels if available. **Challenge:** Create from a file. **Solution:** Use CLI flags for repeatable content. **Interview:** When is CLI faster than UI?

## Lab 065 — List and inspect PRs
**Objective:** Query PR state. **Commands:** `gh pr list`; `gh pr view <number>`. **Expected:** PR metadata is shown. **Task:** Identify author, base, head, and checks. **Challenge:** Filter by state/author. **Solution:** Use supported gh filters. **Interview:** What are base and head branches?

## Lab 066 — Create a PR from CLI
**Objective:** Submit a PR without the browser. **Commands:** `gh pr create --base main --head feature/name --title "..." --body "..."`. **Expected:** PR opens. **Task:** Add an issue reference. **Challenge:** Request reviewers. **Solution:** Use reviewer flags where permitted. **Interview:** What makes a PR automation-friendly?

## Lab 067 — Inspect workflow runs
**Objective:** Diagnose CI from terminal. **Commands:** `gh run list`; `gh run view <run-id>`. **Expected:** Run status and job details appear. **Task:** Identify failed step. **Challenge:** Watch a running job. **Solution:** Use `gh run watch`. **Interview:** What information is needed to debug CI?

## Lab 068 — Call GitHub REST API with gh
**Objective:** Retrieve structured repository data. **Commands:** `gh api repos/OWNER/REPO`. **Expected:** JSON metadata is returned. **Task:** Extract selected fields with a JSON query option if available. **Challenge:** Query issues. **Solution:** Use the REST endpoint path through `gh api`. **Interview:** Why use an API instead of scraping HTML?

## Lab 069 — Automate an API report
**Objective:** Build a small repository report. **Task:** Query repository metadata and recent issues, then save a text/JSON report. **Expected:** Repeatable report generation. **Challenge:** Handle pagination and API failures. **Solution:** Use documented pagination/options and check exit status. **Interview:** What should automation do when an API request fails?

## Lab 070 — Design a safe GitHub automation
**Objective:** Combine CLI, API, and least privilege. **Scenario:** A scheduled report should read issues and workflow status. **Task:** Define required credentials, permissions, inputs, outputs, and failure behavior. **Expected:** A design that does not expose tokens. **Challenge:** Run it in Actions with read-only permissions. **Solution:** Minimize permissions and keep secrets out of logs. **Interview:** What is the principle of least privilege?
